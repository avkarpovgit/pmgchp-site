# pmgchp.ru

Персональный сайт Александра Карпова — юриста по проектному финансированию и ГЧП,
автора телеграм-канала [«Правовой мониторинг ГЧП»](https://t.me/pmgchp).

Статический сайт на [Astro](https://astro.build) + поиск [Pagefind](https://pagefind.app).
Деплой — GitHub Actions → GitHub Pages (ветка `gh-pages`), домен `pmgchp.ru`.

## Структура

- `src/pages/` — страницы: главная, `monitoring` (архив мониторинга), `news` (новости — еженедельный дайджест),
  `blog` (блог), `experience` (опыт / «Обо мне»), `search` (поиск), `terms` (соглашение), `404`
- `src/content/blog/*.md` — посты блога (Markdown с тегами)
- `src/content/monitoring/*.md` — полные тексты выпусков мониторинга (slug = дата начала недели)
- `src/content/news/*.md` — выпуски раздела «Новости» (еженедельный дайджест по ГЧП; slug = дата)
- `src/content/drafts/*.md` — отслеживаемые проекты НПА (законопроекты Госдумы и подзаконные акты); статусы проверяются вручную (см. «Статусы законопроектов»)
- `src/data/monitoring.json` — реестр выпусков для страницы архива (id поста в TG, период, оглавление)
- `src/layouts/Base.astro` — общий лейаут: SEO-разметка, тёмная тема, свайп-навигация, Метрика
- `scripts/validate_monitoring.py` — валидатор данных мониторинга (`--fix` удаляет дубли)
- `scripts/check_dist.py` — smoke-проверка собранного `dist/` (обязательные файлы + внутренние ссылки)
- `scripts/_archive/` — выведенные из эксплуатации скрипты (см. `scripts/_archive/README.md`)
- `public/files/` — PDF-документы, `public/images/` — фото и логотипы

## Автоматизация (GitHub Actions)

`.github/workflows/deploy.yml` — только сборка и деплой:

- **пуш в `main`** (или ручной запуск через `workflow_dispatch`) → валидация данных →
  сборка (`astro build` + Pagefind) → smoke-check (`check_dist.py`) → деплой в `gh-pages`.

Автообновлений по расписанию нет. Контент ведётся вручную: выпуски мониторинга — site-first (см. ниже),
статусы законопроектов проверяются вручную (см. «Статусы законопроектов»). Прежний авто-импорт выпусков
из телеграм-канала выведен из эксплуатации — скрипт в `scripts/_archive/`.

## Как добавить пост в блог

Создать `src/content/blog/YYMMDD_slug.md`:

```markdown
---
title: Заголовок
description: Описание для ленты и SEO
date: 2026-06-12
tags: ["концессии"]
---

Текст в Markdown.
```

## Как добавить выпуск мониторинга

Процесс **site-first**: выпуск сначала публикуется на сайте, затем отдельно готовится текст поста
для Telegram и размещается в канале вручную. `tgId` проставляется после публикации в канале.

1. Добавить запись в начало `src/data/monitoring.json`: `{"id": <id поста в TG>, "date": "YYYY-MM-DD", "period": "...", "items": [...]}`.
2. (Опционально) положить полный текст в `src/content/monitoring/<дата-начала>.md`
   с frontmatter `title`, `period`, `date`, `tgId` — страница появится автоматически,
   архив сошлётся на неё по `tgId`.
3. Проверить: `python3 scripts/validate_monitoring.py`.

## Статусы законопроектов (проверка вручную)

Отслеживаемые проекты — карточки `src/content/drafts/<номер>.md` (напр. `1259047-8.md`). Поля
`status` и `stages` держатся **вручную**: автообновление с СОЗД отключено (портал блокирует IP-адреса
GitHub Actions, из-за чего запросы отваливались по таймауту). Как проверить статус проекта:

1. Открыть паспорт на СОЗД: `https://sozd.duma.gov.ru/bill/<номер>` → блок «Хронология рассмотрения».
2. Взять **самую продвинутую реально состоявшуюся** стадию — у события должна стоять дата `ДД.ММ.ГГГГ`.
   Стадии из трекера с пометкой «Дата события не определена» ещё **не** наступили — их игнорировать.
3. Не путать предложения комитета с решениями палаты (частая ошибка):
   - «предложить принять законопроект **к рассмотрению**» / «…**в первом чтении**» — это Совет Госдумы
     что-то *предлагает*, стадия ещё не пройдена;
   - реальное принятие — событие вида «Рассмотрение законопроекта Государственной Думой `ДД.ММ.ГГГГ`
     **принять** законопроект в первом чтении».
4. Проставить `status` по словарю (от ранней стадии к поздней):
   `На рассмотрении` → `Принят в I чтении` → `Принят во II чтении` → `Принят Госдумой` →
   `Направлен в Совет Федерации` → `Одобрен Советом Федерации` → `Подписан Президентом` → `Опубликован`.
5. Дописать новую стадию в `stages` (`date` = дата события), сохранив стиль соседних записей.
   При сомнениях сверяться с паспортом проекта в КонсультантПлюс.

Когда проект принят как закон — перенести карточку в архив: выставить `archived: true`,
`status: "Опубликован"` и заполнить `lawNumber` (напр. `195-ФЗ`), `lawDate`, `pravo`
(`http://publication.pravo.gov.ru/Document/View/<номер публикации из СОЗД>`) и `lawConsultant`
(текст закона в КонсультантПлюс, `base=LAW`). Карточка уйдёт со страницы проектов на
`/monitoring/drafts/archive`.

## Локальная разработка

```bash
npm install
npm run dev                              # http://localhost:4321 (поиск работает только после build)
npm run build                            # сборка + индекс Pagefind в dist/
python3 scripts/validate_monitoring.py   # проверка данных мониторинга на дубли и дефекты
```
